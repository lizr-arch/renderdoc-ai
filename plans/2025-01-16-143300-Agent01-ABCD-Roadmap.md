## 📋 Executive Summary

本文档规划了 RDC Analyzer 工具的四个主要开发方向，旨在将其从一组分散的分析脚本演进为完整的 RenderDoc 捕获分析解决方案。

| 方向 | 名称 | 优先级 | 预估工时 | 依赖 |
|------|------|--------|----------|------|
| **A** | 端到端集成 | 🔴 高 | 4-6h | - |
| **B** | Shader 源码提取 | 🔴 高 | 3-4h | A |
| **C** | 性能分析功能 | 🟡 中 | 6-8h | A |
| **D** | RenderDoc Extension 集成 | 🟢 低 | 4-6h | A, B, C |

**推荐执行顺序**: A → B → C → D

## 🎯 方向 A: 端到端集成 (End-to-End Integration)

### A.1 目标
将所有分散的分析脚本整合为一个统一的命令行工具，支持一键分析 RDC 文件并生成完整的 HTML 报告。

### A.2 当前状态

```python
class AnalysisPipeline:
    def __init__(self, rdc_path: str, output_dir: str, options: AnalysisOptions):
        self.rdc_path = rdc_path
        self.output_dir = output_dir
        self.options = options
        
    def run(self, progress_callback=None):
        # Step 1: 打开 RDC 文件
        capture = self._open_capture()
        
        # Step 2: 解析事件列表
        events = self._parse_events(capture)
        
        # Step 3: 提取管线状态
        states = self._extract_states(capture, events)
        
        # Step 4: 运行规则分析
        findings = self._analyze_rules(states)
        
        # Step 5: 采样资源数据
        resources = self._sample_resources(capture, states)
        
        # Step 6: 生成报告
        self._export_reports(events, states, findings, resources)
        
        return AnalysisResult(...)
```

#### B.3.1 Shader 提取器
- [ ] **B.3.1.1** 创建 `scripts/rdc_analyzer/core/shader_extractor.py`

```python
class ShaderExtractor:
    def __init__(self, controller: ReplayController):
        self.controller = controller
        
    def get_bound_shaders(self, event_id: int) -> Dict[str, ShaderInfo]:
        """获取指定事件绑定的所有着色器"""
        self.controller.SetFrameEvent(event_id, True)
        state = self.controller.GetPipelineState()
        
        shaders = {}
        for stage in ['VS', 'PS', 'GS', 'HS', 'DS', 'CS']:
            shader_id = self._get_shader_id(state, stage)
            if shader_id:
                shaders[stage] = self._extract_shader_info(shader_id, stage)
        return shaders
        
    def disassemble(self, shader_id: ResourceId, target: str = 'HLSL') -> str:
        """反汇编着色器"""
        reflection = self.controller.GetShaderReflection(shader_id)
        return self.controller.DisassembleShader(
            self.controller.GetResourceId(),  # pipeline
            reflection,
            target
        )
```

#### C.2.2 启发式瓶颈检测
| 规则 ID | 名称 | 检测逻辑 |
|---------|------|----------|
| PERF001 | 过大 Draw Call | 顶点数 > 100K |
| PERF002 | 过多 Draw Call | 帧内 Draw > 2000 |
| PERF003 | 冗余状态切换 | 连续设置相同状态 |
| PERF004 | 大纹理采样 | 单 Pass 绑定 > 8 个大纹理 |
| PERF005 | 过度绘制 | 相同像素多次写入 |
| PERF006 | 低效格式 | 使用未压缩纹理 |
| PERF007 | 全屏 Pass 过多 | 后处理链过长 |

#### C.3.1 性能分析器
- [ ] **C.3.1.1** 创建 `scripts/rdc_analyzer/analyzers/performance.py`

```python
class PerformanceAnalyzer:
    def __init__(self, controller: ReplayController):
        self.controller = controller
        
    def analyze_frame(self, events: List[ActionDescription]) -> FrameStats:
        """分析整帧性能"""
        stats = FrameStats()
        
        for event in events:
            if event.IsDraw():
                stats.total_draw_calls += 1
                stats.total_vertices += event.numIndices or event.numVertices
                
        return stats
        
    def detect_bottlenecks(self, stats: FrameStats) -> List[PerfFinding]:
        """检测性能瓶颈"""
        findings = []
        
        if stats.total_draw_calls > 2000:
            findings.append(PerfFinding(
                rule_id='PERF002',
                severity='warning',
                message=f'Draw call count ({stats.total_draw_calls}) exceeds recommended limit'
            ))
            
        return findings
```

## 🔧 技术决策记录

### TD-001: 统一入口 vs 模块化脚本
**决策**: 创建统一 CLI 入口，同时保留模块化调用能力
**原因**: 方便用户一键使用，同时支持高级用户自定义流程

### TD-002: 着色器反汇编目标
**决策**: 默认使用 HLSL（如果可用），回退到 ASM
**原因**: HLSL 可读性更高，ASM 保证总是可用

### TD-003: 扩展安装方式
**决策**: 提供自动安装脚本，复制到用户目录
**原因**: 避免修改 RenderDoc 安装目录，支持多版本
