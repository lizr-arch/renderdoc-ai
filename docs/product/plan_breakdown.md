# 开发流程与分工（草案）

## 里程碑与顺序（按依赖/重要度）
1) **模板统一与报告双适配**（高优先）  
   - 目标：GUI/离线共用 HTML/JS/CSS 模板；适配器区分数据源（ReplayController vs XML/JSON）。  
   - 依赖：无（可直接抽取现有模板）。  
2) **离线报告增强**（高优先，依赖 M1）  
   - 轻量/全量模式、缺失字段提示、JSON 快照输出、过滤参数一致性。  
   - 依赖：模板统一。  
3) **MCP 稳定与示例脚本**（高优先）  
   - 扩展兼容（线程/Qt 回退）、健康检查；样例：计时热点、管线反查、资源抽取、局部导出。  
   - 依赖：扩展已可加载（当前 OK）。  
4) **Skill 落地**（中优先，依赖 MCP/快照）  
   - 安装/自检动作集；增值分析动作集（瓶颈归因、Shader 公式提取、管线审阅、回归对比、脚本生成）。  
   - 依赖：MCP 可用；有报告/快照结构定义。  
5) **GUI 报告集成**（中优先，依赖模板统一）  
   - 按新模板生成，附 JSON 快照；按钮参数（截图/缩略/轻量）。  
6) **对比与 CI 友好**（后续，依赖离线增强）  
   - 差异高亮、体积控制、退出码/统计。

## 分工（3 人）
- **Dev A：MCP + SKILL**  
  - 稳定扩展加载（PySide2/6/线程）、健康检查脚本。  
  - MCP 示例脚本（计时、管线、反查、资源导出）。  
  - Skill：安装/自检 + 增值分析动作，实现与文档。  
  - 交付物：`tools/mcp/*` 更新，`docs/product/skill_design.md` 落地实现，样例脚本。
- **Dev B：GUI 报告**  
  - 抽模板适配器（ReplayController）；导出按钮参数；生成 JSON 快照。  
  - 交付物：GUI 导出代码/脚本、`docs/product/gui_report.md` 验收清单。
- **Dev C：离线报告 + HTML 模板**  
  - 抽共用模板；CLI 轻量/全量模式、过滤对齐；缺失提示；JSON 快照。  
  - 交付物：`scripts/rdc_analyzer/*`，模板文件，`docs/product/offline_report.md` 验收清单。

## 依赖关系（简表）
- 模板统一（Dev C） → GUI 集成（Dev B）、离线增强（Dev C 后续）、Skill 可读取统一结构（Dev A）。
- MCP 稳定（Dev A） → Skill 增值分析、局部数据补全。
- JSON 快照格式 → Skill/AI 对比分析、CI 统计。

## 优先级概览
- P0：模板统一；MCP 稳定/健康检查；离线过滤/轻量模式（已有基础，补完）。  
- P1：GUI 导出接入新模板+快照；Skill 落地。  
- P2：对比/CI 增强。

## 文档/协作规范
- 设计/实现文档位置：`docs/product/`（总方针/子功能），`docs/learn/architecture/`（架构），`docs/learn/evidence/`（实测）。  
- 每人维护对应子文档的“验收清单”与“已知缺口”，更新同文件。  
- 代码注释简洁，引用文档路径。  
- AGENTS.MD 可增补分工与流程说明：  
  - 增加“模板统一优先”、“报告不重复生成”、“MCP 不产整报告”原则；  
  - 增加协作约定：模板改动先通知 Dev B/C；MCP 接口变更先通知 Skill 开发。  

## 提交与验证
- 统一 JSON 快照 schema（含来源标识 GUI/Offline/MCP、字段可用性）。  
- 每个里程碑需要最小 demo + 文档更新。  
- 关键脚本需带示例命令与预期输出（文档内给出）。
