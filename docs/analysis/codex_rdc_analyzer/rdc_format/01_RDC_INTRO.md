## 一、RDC 是什么？

### 类比：RDC 就像"游戏录像"

想象你在玩一个游戏，你按下了"录像"按钮，游戏会把这一帧画面是怎么画出来的全部记录下来。

**RDC 文件就是这个"录像"**：
- 它记录了 GPU 画这一帧时的**每一个命令**（比如"画一个三角形"、"使用这张贴图"）
- 它还保存了画面需要的**所有素材**（纹理图片、3D 模型数据等）

```
你玩游戏的一帧画面
        ↓
    RenderDoc 捕获
        ↓
    capture.rdc 文件（这就是我们要分析的东西）
```

## 二、RDC 文件的整体结构

### 类比：RDC 就像一本"书"

把 RDC 文件想象成一本书：

```
┌─────────────────────────────────────────────┐
│                 一本书                       │
├─────────────────────────────────────────────┤
│  📖 封面信息 (书名、作者、出版日期)           │  ← FileHeader（文件头）
│  🖼️ 封面图片                                │  ← Thumbnail（缩略图）
│  📝 内容简介 (这本书讲什么)                   │  ← Metadata（元数据）
│  📚 第一章、第二章、第三章...                 │  ← Sections（章节）
│      └── 每章里的段落和句子                  │  ← Chunks（具体内容）
└─────────────────────────────────────────────┘
```

**对应到 RDC 文件**：

| 书的部分 | RDC 对应 | 存了什么 |
|----------|----------|----------|
| 封面信息 | FileHeader | 文件格式版本、RenderDoc 版本 |
| 封面图片 | Thumbnail | 捕获时的画面截图（JPG） |
| 内容简介 | Metadata | 用的什么 GPU、什么图形 API |
| 各个章节 | Sections | 不同类型的数据块 |
| 章节内容 | Chunks | 每一条 GPU 命令 |

---

## 三、核心概念速记

| 概念 | 一句话解释 |
|------|------------|
| **RDC 文件** | GPU 绘制一帧的完整录像 |
| **FileHeader** | 文件身份证（"我是 RDC v1.2"） |
| **Thumbnail** | 预览图（JPG 格式） |
| **Metadata** | 环境信息（用的什么 GPU、什么 API） |
| **Section** | 数据分类（FrameCapture 最重要） |
| **Chunk** | 单条 GPU 命令（如"画三角形"） |

## 四、项目如何解析 RDC

### 解析流程总览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           解析流程                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   capture.rdc                                                           │
│       │                                                                 │
│       ▼                                                                 │
│   ┌─────────────────────────────────────────┐                          │
│   │  步骤 1: 调用 renderdoccmd.exe          │                          │
│   │         把 RDC 转换成 XML               │                          │
│   └─────────────────────────────────────────┘                          │
│       │                                                                 │
│       │  renderdoccmd convert -c xml capture.rdc output.xml            │
│       ▼                                                                 │
│   ┌─────────────────────────────────────────┐                          │
│   │  步骤 2: 读取 XML 文件                   │                          │
│   │         提取所有 Chunk 数据              │                          │
│   └─────────────────────────────────────────┘                          │
│       │                                                                 │
│       ▼                                                                 │
│   ┌─────────────────────────────────────────┐                          │
│   │  步骤 3: 整理成统一的 JSON 格式          │                          │
│   │         方便后续分析                     │                          │
│   └─────────────────────────────────────────┘                          │
│       │                                                                 │
│       ▼                                                                 │
│   CaptureData (JSON)                                                    │
│   ├── meta: GPU型号、API类型                                            │
│   ├── events: 所有绘制命令列表                                          │
│   ├── textures: 所有纹理信息                                            │
│   └── buffers: 所有缓冲区信息                                           │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 为什么要先转成 XML？

直接解析 RDC 的二进制很复杂（需要处理压缩、不同 API 的不同格式等）。

**RenderDoc 官方提供了一个工具 `renderdoccmd`**，它可以把二进制 RDC 转成人类可读的 XML：

```xml
<!-- 转换后的 XML 示例 -->
<chunks>
  <chunk id="101" name="vkCmdBeginRenderPass">
    <RenderPass>
      <RenderArea x="0" y="0" width="1920" height="1080"/>
      <ColorAttachment index="0" format="VK_FORMAT_R8G8B8A8_UNORM"/>
    </RenderPass>
  </chunk>
  
  <chunk id="104" name="vkCmdDraw">
    <vertexCount>3000</vertexCount>
    <instanceCount>1</instanceCount>
  </chunk>
</chunks>
```

**这样解析就简单多了**：用 Python 的 `xml.etree` 就能读取！
