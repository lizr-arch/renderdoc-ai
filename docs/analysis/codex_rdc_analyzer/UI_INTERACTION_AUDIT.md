## 5. 开发优先级建议

### 5.1 P0: 立即修复（阻塞核心功能）

1. **ResourceUsageIndex 构建**
   - 填充 `texture.usedBy` 和 `shader.usedBy`
   - 实现资源 → DrawCall 反向索引
   - **影响**: textures.html 和 shaders.html 的"使用情况"功能

2. **URL 参数跳转机制**
   - 实现 `?id=xxx&highlight=true` 参数解析
   - 页面加载时自动滚动并高亮目标元素
   - **影响**: 所有跨页面跳转功能

### 5.2 P1: 近期完善（增强用户体验）

3. **EvidenceChain 数据填充**
   - 为每个 Issue 添加 `evidence_chain` 和 `actions`
   - **影响**: 问题可追溯性

4. **纹理缩略图导出**
   - 在 Bundle 生成时导出缩略图
   - **影响**: events.html 纹理绑定显示

### 5.3 P2: 后续优化（可选增强）

5. **RGBA 通道切换实现** - Canvas 2D 或 WebGL
6. **对比功能增强** - 差异高亮
7. **搜索增强** - 模糊匹配、历史记录

## 7. 结论

### 7.1 总体评价

**现有 UI 框架基础良好，62% 的交互组件正常工作**。主要问题是**数据层缺失**，而非 UI 层问题。

### 7.2 核心建议

1. **保留现有 4 页面架构** - UI 设计成熟，改造成本低于重写
2. **优先填充数据层** - ResourceUsageIndex 是解锁多个交互功能的关键
3. **实现跳转机制** - URL 参数是"证据链"UX 的核心基础设施
4. **暂缓低优先级功能** - RGBA 通道、AI 优化等可后期迭代

### 7.3 下一步行动

开始实现 **P0: ResourceUsageIndex** 构建，这将解锁：
- textures.html "使用情况" 列表
- shaders.html "使用情况" 列表  
- 问题卡片的"跳转到证据"功能
