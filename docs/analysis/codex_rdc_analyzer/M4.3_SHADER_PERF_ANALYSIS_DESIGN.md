## 1. 概述

### 1.1 目标

在 shaders.html 页面提供**基于 Mali Offline Compiler (malioc) 的多维度 Shader 性能评估**，帮助开发者快速定位性能问题并获得具体优化建议。

### 1.2 核心能力

| 维度 | 数据来源 | 输出 |
|------|----------|------|
| **静态复杂度** | malioc Cycles (A/LS/T/V) | 周期数、瓶颈类型 |
| **寄存器压力** | malioc Registers | 工作寄存器数、Occupancy 影响 |
| **动态影响** | 帧上下文 | Draw Count × 像素覆盖率 |
| **健康评分** | 加权公式 | 0-100 分 + CRITICAL/WARNING/INFO |
| **优化建议** | 规则引擎 | 9 条规则 → 具体建议 |

### 1.3 官方参考

- [ARM Mali Best Practices Guide](https://developer.arm.com/documentation/102073/latest/)
- [ARM Mali Register Pressure Guide](https://developer.arm.com/documentation/102643/latest/)
- [Vulkan Samples - 16-bit Storage](https://github.com/KhronosGroup/Vulkan-Samples/tree/main/samples/performance/16bit_storage_input_output)

## 2. 数据模型

### 2.1 CycleMetrics（周期指标）

```python
@dataclass
class CycleMetrics:
    arithmetic: float     # A: 算术运算周期
    load_store: float     # LS: 内存访问周期
    texture: float        # T: 纹理采样周期
    varying: float        # V: 插值器周期
    bound: str            # 瓶颈类型: "A" | "LS" | "T" | "V"
    
    @property
    def total(self) -> float:
        """取最大值（流水线并行）"""
        return max(arithmetic, load_store, texture, varying)
```

### 2.2 RegisterMetrics（寄存器指标）

```python
@dataclass
class RegisterMetrics:
    work_registers: int       # 工作寄存器数量
    uniform_registers: int    # Uniform 寄存器数量
    stack_spilling: bool      # 是否溢出到栈
    
    # 阈值定义 (ARM 最佳实践)
    THRESHOLD_WARNING = 32    # 32+ 开始影响 Occupancy
    THRESHOLD_CRITICAL = 48   # 48+ 严重影响并行度
    THRESHOLD_MAX = 64        # Mali 最大寄存器数
    
    @property
    def occupancy_factor(self) -> float:
        """
        Occupancy 惩罚系数
        公式: 1.0 + max(0, (registers - 32) / 32) * 0.3
        """
```

### 2.3 DynamicMetrics（动态帧上下文）

```python
@dataclass
class DynamicMetrics:
    draw_count: int               # Shader 一帧内调用次数
    viewport_width: int           # 视口宽度
    viewport_height: int          # 视口高度
    estimated_coverage: float     # 像素覆盖率估算 (0.0 - 1.0)
    pass_name: str                # Pass 名称（用于覆盖率启发式）
```

**覆盖率启发式规则**：

| Pass 类型 | 关键词 | 覆盖率 |
|-----------|--------|--------|
| 全屏后处理 | post, bloom, blur, ao, fxaa, tonemap | 100% |
| 阴影 | shadow | 50% |
| UI | ui, hud | 20% |
| 粒子 | particle, vfx | 10% |
| 默认 | - | 50% |

### 2.4 ShaderPerfResult（分析结果）

```python
@dataclass
class ShaderPerfResult:
    shader_name: str
    shader_type: str              # "vertex" | "fragment" | "compute"
    gpu_target: str               # "Mali-G78"
    
    cycles: CycleMetrics
    registers: RegisterMetrics
    dynamic: DynamicMetrics
    
    health_score: int             # 0-100 分
    health_level: HealthLevel     # CRITICAL | WARNING | INFO
    weighted_cost: float          # 加权成本 (MCP)
    
    triggered_rules: List[str]    # ["R1", "R5"]
    recommendations: List[ShaderRecommendation]
```

## 3. 评分算法

### 3.1 Cycles 评分

| Cycles 范围 | 评分 | 说明 |
|-------------|------|------|
| ≤ 8 | 100 | 优秀 |
| 8 - 14 | 100 → 80 | 良好（线性下降） |
| 14 - 20 | 80 → 60 | 警告（线性下降） |
| > 20 | 60 → 0 | 危险（快速下降，每 cycles -3 分） |

### 3.2 寄存器评分

| 寄存器数 | 评分 | 说明 |
|----------|------|------|
| ≤ 16 | 100 | 优秀 |
| 16 - 32 | 100 → 85 | 良好 |
| 32 - 48 | 85 → 55 | 警告（影响 Occupancy） |
| > 48 | 55 → 10 | 严重（快速下降） |
| Stack Spilling | 20 | 直接严重扣分 |

### 3.3 加权成本公式

```
pixel_work = cycles × viewport_pixels × coverage × draw_count
weighted_cost = pixel_work × register_penalty

单位: Mega-Cycle-Pixels (MCP)
```

**register_penalty 计算**：
```
1.0 + max(0, (registers - 32) / 32) × 0.3

示例:
- 32 寄存器: 1.0 (无惩罚)
- 48 寄存器: 1.15 (15% 惩罚)
- 64 寄存器: 1.30 (30% 惩罚)
```

### 3.4 综合健康评分

```
base = cycles_score × 0.4 + register_score × 0.3 + 30
final = base - critical_rules × 15 - warning_rules × 5

等级判定:
- score < 40 或 有 CRITICAL 规则 → CRITICAL
- score < 70 或 有 WARNING 规则 → WARNING
- 其他 → INFO
```

## 4. 规则引擎

### 4.1 规则定义

| ID | 名称 | 触发条件 | 级别 | 来源 |
|----|------|----------|------|------|
| **R1** | Stack Spilling | `stack_spilling == true` | 🔴 CRITICAL | malioc |
| **R2** | 全屏高复杂度 | `coverage ≥ 0.8 && cycles ≥ 30` | 🔴 CRITICAL | heuristic |
| **R3** | 极端寄存器压力 | `work_registers ≥ 56` | 🔴 CRITICAL | malioc |
| **R4** | 成本过高 | `weighted_cost > top 10%` | 🔴 CRITICAL | heuristic |
| **R5** | 高 Cycles | `total_cycles ≥ 20` | 🟡 WARNING | ARM Best Practice |
| **R6** | 寄存器压力 | `work_registers ≥ 32` | 🟡 WARNING | ARM Best Practice |
| **R7** | Late Z/S Test | `has_late_zs == true` | 🟡 WARNING | malioc |
| **R8** | Uniform 计算 | `has_uniform_computation == true` | 🟡 WARNING | malioc |
| **R9** | 高复杂度低影响 | `cycles ≥ 20 && coverage < 0.1` | 🟢 INFO | heuristic |

### 4.2 规则→建议映射

| ID | 标题 | 优化建议 |
|----|------|----------|
| **R1** | 减少寄存器使用 | 1. 减少临时变量<br>2. 拆分复杂 Shader<br>3. 使用 FP16 (mediump) |
| **R2** | 优化全屏效果 | 1. 不变计算移到 VS<br>2. 使用 LUT<br>3. 降采样处理 |
| **R3** | 大幅降低寄存器 | 1. 使用 FP16<br>2. 简化算法<br>3. 拆分为多 Pass |
| **R4** | 整体优化热点 | 1. 优化瓶颈管线<br>2. LOD 简化版本<br>3. 减少调用次数 |
| **R5** | 降低复杂度 | 1. 检查冗余采样<br>2. 预计算常量 |
| **R6** | 降低寄存器压力 | 1. 使用 mediump<br>2. 减少临时变量作用域 |
| **R7** | 避免 Late Z/S | 1. 避免 discard<br>2. 不修改 gl_FragDepth |
| **R8** | 预计算 Uniform | 1. 数学运算移到 CPU<br>2. 预计算矩阵变换 |
| **R9** | 考虑简化版本 | 1. 创建 LOD 版本<br>2. 当前可能不需优化 |

## 6. UI 集成

### 6.1 shaders.html 增强

**新增元素**：

1. **GPU 选择下拉框** - 按档位分组，支持切换目标 GPU
2. **健康评分徽章** - 每个 Shader 卡片显示 0-100 分 + 颜色
3. **多维度指标网格** - A/LS/T/V 周期、寄存器、覆盖率
4. **加权成本条** - 可视化 weighted_cost 占比
5. **问题检测列表** - 触发的规则 + 建议

### 6.2 数据流

```
RDC → malioc → JSON → shader_perf_analyzer.py → ShaderPerfResult
                                                      ↓
                                           shaders.html 渲染
```

### 6.3 前端兼容性

支持两种数据格式：

1. **新格式** (带 maliAnalysis): 完整 Cycles/Registers/DynamicMetrics
2. **旧格式** (无 malioc): 仅显示基础信息，隐藏分析面板
