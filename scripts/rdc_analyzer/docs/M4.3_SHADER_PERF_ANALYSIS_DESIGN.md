# M4.3 设计文档：Mali Shader 性能多维度分析

> **版本**: 1.0.0  
> **创建日期**: 2025-02-07  
> **状态**: Draft  
> **前置依赖**: Mali Offline Compiler (malioc) 可用

## 1. 概述

### 1.1 目标

构建基于 Mali Offline Compiler 的 Shader 性能多维度分析系统，提供：

1. **静态复杂度分析**：基于 malioc cycles 数据
2. **动态成本评估**：结合 Draw Call 次数和像素覆盖率
3. **问题自动检测**：基于规则引擎的性能问题识别
4. **优化建议生成**：基于 ARM 官方最佳实践

### 1.2 核心观点

> **单纯看 Shader 的 cycles 数量是不够的，还需要考虑这个 Shader 实际渲染了多少像素**

这是本方案的核心设计理念，与 ARM 官方文档的带宽计算公式一致：

```
实际成本 = Cycles per Fragment × 渲染像素数 × 调用次数
```

### 1.3 官方最佳实践来源

| 来源 | URL | 关键内容 |
|------|-----|----------|
| Vulkan Samples - 16bit Storage | docs.vulkan.org | FP16 varying 节省 50% 带宽 |
| Vulkan Samples - 16bit Arithmetic | docs.vulkan.org | 寄存器压力影响 occupancy |
| Vulkan Samples - MSAA | docs.vulkan.org | 带宽公式: resolution × depth × fps |
| Unity Shader Optimization | docs.unity3d.com | 通用 Shader 优化建议 |

## 3. 评分算法

### 3.1 静态复杂度评分

```python
def score_cycles(total_cycles: float) -> int:
    """
    基于 malioc total cycles 评分
    
    阈值来源:
    - 14 cycles: 业界经验警告阈值
    - 30 cycles: 全屏 Shader 严重阈值
    - 100 cycles: 极端复杂 Shader
    """
    if total_cycles <= 8:
        return 100  # 优秀
    elif total_cycles <= 14:
        return 85   # 良好
    elif total_cycles <= 30:
        return 60   # 需关注
    elif total_cycles <= 60:
        return 40   # 警告
    else:
        return max(10, 100 - int(total_cycles))  # 严重
```

### 3.2 寄存器压力评分

```python
def score_registers(work_registers: int, stack_spilling: bool) -> int:
    """
    基于寄存器使用评分
    
    来源: ARM 文档 - "GPU performance is in large part dictated by 
    how many registers are required to run shaders"
    
    Mali GPU 典型配置:
    - 32 registers: 正常 occupancy
    - 48 registers: 降低 occupancy
    - 64+ registers: 严重影响性能
    """
    if stack_spilling:
        return 0  # 栈溢出是严重问题
    
    if work_registers <= 24:
        return 100
    elif work_registers <= 32:
        return 85
    elif work_registers <= 48:
        return 60
    elif work_registers <= 64:
        return 35
    else:
        return 10
```

### 3.3 覆盖率估算

```python
def estimate_coverage(pass_types: List[str], draw_count: int) -> float:
    """
    根据 Pass 类型估算像素覆盖率
    
    设计原则:
    - PostProcess/Fullscreen: 100% 覆盖
    - UI: 通常 5% 左右
    - Shadow: 约 30% (取决于光源数)
    - 普通场景: 默认 10%
    """
    # Pass 类型到覆盖率的映射
    COVERAGE_MAP = {
        'postprocess': 1.0,
        'fullscreen': 1.0,
        'bloom': 1.0,
        'tonemapping': 1.0,
        'fxaa': 1.0,
        'ssao': 0.8,
        'ssr': 0.6,
        'shadow': 0.3,
        'shadowmap': 0.3,
        'ui': 0.05,
        'hud': 0.05,
        'particle': 0.15,
        'transparent': 0.2,
        'opaque': 0.1,
        'default': 0.1
    }
    
    # 匹配 Pass 类型
    max_coverage = 0.1  # 默认值
    for pass_type in pass_types:
        pass_lower = pass_type.lower()
        for key, coverage in COVERAGE_MAP.items():
            if key in pass_lower:
                max_coverage = max(max_coverage, coverage)
                break
    
    return min(1.0, max_coverage)
```

### 3.4 加权成本计算

```python
def calculate_weighted_cost(
    cycles: float,
    coverage: float,
    draw_count: int,
    viewport_pixels: int,
    registers: int
) -> float:
    """
    计算 Shader 的加权成本
    
    公式: Cost = Cycles × Pixels × Draws × RegisterPenalty
    
    这是本方案的核心公式，整合了：
    1. 静态复杂度 (cycles)
    2. 动态覆盖 (coverage × pixels)
    3. 调用频率 (draw_count)
    4. 占用率惩罚 (register_penalty)
    """
    # 基础像素工作量
    pixel_work = cycles * viewport_pixels * coverage * draw_count
    
    # 寄存器惩罚系数 (超过 32 逐步增加)
    register_penalty = 1.0 + max(0, (registers - 32) / 32) * 0.3
    
    # 加权成本 (单位: cycles)
    weighted_cost = pixel_work * register_penalty
    
    # 转换为 M cycles
    return weighted_cost / 1e6
```

### 3.5 综合健康评分

```python
def calculate_health_score(
    cycle_score: int,
    register_score: int,
    weighted_cost: float,
    issues: List[ShaderIssue]
) -> int:
    """
    综合健康评分 (0-100)
    
    权重分配:
    - 静态复杂度: 30%
    - 寄存器压力: 25%
    - 加权成本: 35%
    - 问题惩罚: 10%
    """
    # 加权成本评分
    if weighted_cost < 10:
        cost_score = 100
    elif weighted_cost < 50:
        cost_score = 80
    elif weighted_cost < 100:
        cost_score = 60
    elif weighted_cost < 200:
        cost_score = 40
    else:
        cost_score = 20
    
    # 问题惩罚
    critical_count = sum(1 for i in issues if i.severity == 'critical')
    warning_count = sum(1 for i in issues if i.severity == 'warning')
    issue_penalty = critical_count * 15 + warning_count * 5
    
    # 加权平均
    base_score = (
        cycle_score * 0.30 +
        register_score * 0.25 +
        cost_score * 0.35 +
        100 * 0.10  # 基准分
    )
    
    return max(0, min(100, int(base_score - issue_penalty)))
```

## 4. 规则引擎

### 4.1 规则定义表

| 规则 ID | 名称 | 检测条件 | 严重度 | 来源 |
|---------|------|----------|--------|------|
| R1 | 栈溢出 | `stack_spilling == true` | 🔴 Critical | malioc |
| R2 | 全屏高复杂度 | `cycles > 30 && coverage > 0.5` | 🔴 Critical | ARM Best Practice |
| R3 | 极端寄存器压力 | `work_registers > 48` | 🔴 Critical | ARM Occupancy |
| R4 | 综合成本过高 | `weighted_cost > 100M` | 🔴 Critical | 计算公式 |
| R5 | 高 Cycles | `cycles > 14` | 🟡 Warning | 业界经验 |
| R6 | 寄存器压力 | `work_registers > 32` | 🟡 Warning | ARM 文档 |
| R7 | Late Z/S | `late_zs_test == true` | 🟡 Warning | malioc |
| R8 | Uniform 计算 | `has_uniform_computation == true` | 🟡 Warning | malioc |
| R9 | 高 Cycles 低成本 | `cycles > 50 && weighted_cost < 10M` | 🟢 Info | 覆盖率分析 |

### 4.2 规则实现

```python
class ShaderIssueDetector:
    """Shader 问题检测器"""
    
    RULES = [
        {
            "id": "R1",
            "name": "Stack Spilling",
            "severity": "critical",
            "check": lambda ctx: ctx.mali_result.registers.stack_spilling if ctx.mali_result else False,
            "title": "寄存器溢出到栈内存",
            "description": "Shader 使用的寄存器超出硬件限制，溢出到栈内存会严重影响性能",
            "source": "malioc"
        },
        {
            "id": "R2", 
            "name": "Fullscreen High Complexity",
            "severity": "critical",
            "check": lambda ctx: (
                ctx.mali_result and 
                ctx.mali_result.cycles.total > 30 and 
                ctx.coverage_ratio > 0.5
            ),
            "title": "全屏 Shader 复杂度过高",
            "description": "高覆盖率 + 高 Cycles 是性能的主要瓶颈",
            "source": "arm_best_practice"
        },
        {
            "id": "R3",
            "name": "Extreme Register Pressure",
            "severity": "critical", 
            "check": lambda ctx: (
                ctx.mali_result and
                ctx.mali_result.registers.work > 48
            ),
            "title": "极端寄存器压力",
            "description": "寄存器使用超过 48 会严重降低 GPU 占用率 (occupancy)",
            "source": "arm_best_practice"
        },
        {
            "id": "R4",
            "name": "High Weighted Cost",
            "severity": "critical",
            "check": lambda ctx: ctx.weighted_cost > 100,
            "title": "综合成本过高",
            "description": "加权成本超过 100M cycles，是帧内的主要性能瓶颈",
            "source": "heuristic"
        },
        {
            "id": "R5",
            "name": "High Cycles",
            "severity": "warning",
            "check": lambda ctx: (
                ctx.mali_result and
                ctx.mali_result.cycles.total > 14
            ),
            "title": "Shader 复杂度偏高",
            "description": "总 Cycles 超过 14，建议检查是否可以优化",
            "source": "industry_experience"
        },
        {
            "id": "R6",
            "name": "Register Pressure",
            "severity": "warning",
            "check": lambda ctx: (
                ctx.mali_result and
                ctx.mali_result.registers.work > 32 and
                ctx.mali_result.registers.work <= 48
            ),
            "title": "寄存器压力",
            "description": "寄存器使用超过 32，可能影响 GPU 占用率",
            "source": "arm_best_practice"
        },
        {
            "id": "R7",
            "name": "Late Z/S Test",
            "severity": "warning",
            "check": lambda ctx: (
                ctx.mali_result and
                getattr(ctx.mali_result, 'late_zs_test', False)
            ),
            "title": "延迟深度测试",
            "description": "Shader 禁用了 Early-Z 优化，可能导致过度绘制",
            "source": "malioc"
        },
        {
            "id": "R8",
            "name": "Uniform Computation",
            "severity": "warning",
            "check": lambda ctx: (
                ctx.mali_result and
                ctx.mali_result.has_uniform_computation
            ),
            "title": "Uniform 计算",
            "description": "Shader 中存在可移至 CPU 的 Uniform 计算",
            "source": "malioc"
        },
        {
            "id": "R9",
            "name": "High Cycles Low Impact",
            "severity": "info",
            "check": lambda ctx: (
                ctx.mali_result and
                ctx.mali_result.cycles.total > 50 and
                ctx.weighted_cost < 10
            ),
            "title": "高复杂度低影响",
            "description": "虽然 Cycles 较高，但由于覆盖率低，实际影响有限",
            "source": "coverage_analysis"
        }
    ]
    
    def detect_issues(self, ctx: ShaderPerformanceContext) -> List[ShaderIssue]:
        issues = []
        for rule in self.RULES:
            if rule["check"](ctx):
                issues.append(ShaderIssue(
                    rule_id=rule["id"],
                    severity=rule["severity"],
                    title=rule["title"],
                    description=rule["description"],
                    source=rule["source"],
                    # metric_name 和 metric_value 需要根据规则动态填充
                ))
        return issues
```

## 附录 A: ARM 官方建议摘要

### A.1 关于 16-bit 精度

> "Use FP16 vertex outputs when possible and meets quality requirements."
> 
> — Vulkan Samples: 16-bit Storage

### A.2 关于寄存器压力

> "GPU performance is in large part dictated by how many registers are required to run shaders. As more registers are used, fewer threads can run concurrently."
> 
> — Vulkan Samples: 16-bit Arithmetic

### A.3 关于带宽计算

> "1X attachment: 2168 * 1080 * 4 * 60 = 562 bytes/s"
> 
> — Vulkan Samples: MSAA

### A.4 Unity 优化建议

> "Move calculations from the fragment shader to the vertex shader, so they run only for every vertex, not every fragment."
> 
> — Unity Manual: Optimize Shaders
