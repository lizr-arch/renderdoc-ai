# RDC Event 导出：AI 与脚本职责边界

> 更新日期：2026-02-10  
> 目标：明确哪些工作必须脚本完成，哪些适合 AI 增强，避免“AI 重写核心导出逻辑”。

---

## 1. 总原则

- **确定性数据处理必须脚本化**：字节解析、schema 校验、目录产物生成、状态码输出。
- **语义增强可由 AI 参与**：命名建议、材质语义推断、跨文档解释与复核建议。
- **最终可用性由人工验收**：引擎内视觉一致性、材质观感、性能预算。

---

## 2. 边界矩阵

| 工作项 | 脚本负责（必须） | AI 负责（可选增强） | 人工负责 |
|---|---|---|---|
| Event 数据提取 | 从 xml/zip/intermediate 提取结构化数据 | 无 | 抽样复核正确性 |
| Mesh 导出 | 写出 `mesh.obj/mesh.mtl`、索引/拓扑映射 | 命名建议（如角色名、部件名） | 在引擎中检查法线/切线/缩放 |
| Shader 处理 | SPIR-V/DXBC 路由、产出 hlsl/usf 与状态 | 补充可读注释、变量语义猜测 | 选择最终 shader 模板 |
| Texture 处理 | RGBA/RAW 导出、状态落盘 | 贴图用途建议（BaseColor/Normal/Roughness） | 目视检查与压缩策略 |
| Material 组装 | 输出 `materials.json`、绑定槽位 | 槽位归一化建议（跨引擎） | 最终材质网络搭建 |
| 批处理与重试 | 扫描、排序、重跑、summary | 异常聚类与优先级建议 | 决策是否继续批量 |
| 契约验证 | schema 校验、失败即阻断 | 解释错误原因与修复建议 | 接受/驳回变更 |

---

## 3. 为什么不能让 AI 直接做“核心导出”

1. **可重复性风险**：同一输入多次运行结果可能不一致。  
2. **可审计性风险**：难以保证每个字段有明确来源。  
3. **回归风险**：缺少稳定状态机，跨版本容易漂移。  

因此：AI 适合做“解释与建议层”，不适合替代“数据生成层”。

---

## 4. 推荐协作流程

1. 脚本阶段：`extract_event_intermediate` → `export_event_import_bundle` → `export_fbx_assets`。  
2. AI 阶段：读取导出结果，补充语义标签、命名建议、问题摘要。  
3. 人工阶段：在 Unity/Unreal/Messiah 中进行视觉与功能验收。

---

## 5. 失败处理分工

- **脚本失败（硬错误）**：路径缺失、schema 不通过、外部工具不可用 → 立即 fail，输出 status。  
- **AI 失败（软错误）**：语义判断置信度低、无法确认贴图用途 → 标注 `假设（待验证）`，不阻断导出。  
- **人工阻断**：导入后视觉不匹配、材质错误 → 回到脚本层补充数据字段，不靠 AI 猜测兜底。

---

## 6. 对未来 Skill 的约束

- Skill 默认必须调用现有脚本，不得复制其核心算法。
- Skill 输出中必须保留每一步 `status` 和 `data_provenance`。
- Skill 新增字段必须先定义 schema，再允许进入 CI。
